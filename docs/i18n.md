# Internationalization

Life OS ships in **English** (default), **Français** and **العربية** (right-to-left).

## How it works
- Every user-facing string lives in `locales/{en,fr,ar}.json`. Components never contain literal text:
  - React: `const { t } = useI18n(); t('tasks.new')`
  - Outside React (services, pure libs, notifications): `import { t } from '@/i18n'`.
- Keys are grouped by feature (`tasks.*`, `habits.*`, `paywall.*` ...). Data that is stored in the database stays language-neutral (ids such as `Work`, `Ideas`, achievement keys, challenge ids) and is translated only when displayed.
- Plurals use i18next's `_zero/_one/_two/_few/_many/_other` suffixes (Arabic needs all six, English and French need `_one` and `_other`; note French treats 0 as singular).
- Dates, times and weekday names come from `Intl` (`src/i18n/format.ts`) with Western digits (0-9) in every language. The first day of the week follows the language (en Sunday, fr Monday, ar Saturday).
- The language is stored on the profile (`profile.language`), detected from the device on first launch (`expo-localization`), changeable in Onboarding and Settings -> Language, and synced to `profiles.language` for signed-in users. The account's saved language wins on a new device.
- Local notifications are rescheduled when the language changes so their text follows it.

## Right-to-left
- Direction is applied at the root (`DirectionView`: the `direction` style on native, plus `dir` for react-native-web) so rows, tabs, headers and lists mirror immediately.
- Layout code uses logical properties (`start`/`end`, `marginStart`, `paddingEnd`, `alignItems: 'flex-end'`), never `left`/`right`.
- Direction-bearing icons (chevrons, arrows, back, undo, skip, trends) mirror automatically (`Icon`).
- Charts, the segmented control, the pager (`SwipePager`) and sparklines are direction-aware.
- Moving between LTR and RTL also flips the native `I18nManager` flag and reloads the app once (`react-native-restart`) so system-level behaviour (scroll views, gestures, transitions) is native-correct. English <-> French never reloads.
- Arabic typography (`src/theme/arabic.ts`): IBM Plex Sans Arabic (400/500/600/700), zero letter-spacing (tracking breaks Arabic joining), 12% taller line height. Latin runs and numbers inside Arabic sentences are wrapped in LRM marks and the paragraph is pinned with an RLM, so "+20 XP" or "195 / 200 XP" never reorder.
- User-written content (`<Text content>`) follows its own script instead of the UI language.

## Adding a language
1. Copy `locales/en.json` to `locales/<code>.json` and translate every value (keep `{{placeholders}}`, add every plural form the language needs).
2. Add the language to `LANGUAGES` in `src/i18n/index.ts` (name in its own language, flag, `rtl`, Intl tag, first weekday) and to the resources and the `Locale` type.
3. Add a font mapping in `src/theme/arabic.ts` if it needs a non-Latin face.
4. Extend the CHECK constraint on `profiles.language` with a new migration.
5. `npm test` fails until the files agree.

## Tests (`tests/i18n.test.ts`)
Key parity across languages, no empty values, identical placeholders, complete CLDR plural forms, no stray Latin words in Arabic, every dynamic key family translated (achievements, challenges, categories, moods ...), every `t('key')` used in source exists, no literal UI text in JSX, runtime plural/format checks per language, device-language detection, direction reload behaviour, Arabic typography and bidi isolation.
